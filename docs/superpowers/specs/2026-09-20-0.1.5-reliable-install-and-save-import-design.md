# Mistria Tracker 0.1.5 Reliable Install and Save Import Design

## Goal

Ship a Windows-only 0.1.5 patch that installs the optional companion
reliably and lets a player explicitly choose one Fields of Mistria save file
to import existing discoveries. The tracker must never edit a game save,
silently search a user's drives, or depend on the obsolete Desktop backup
folder.

## Scope

This patch covers four connected Windows flows:

1. The NSIS installer copies the optional companion to a validated Fields of
   Mistria game folder and proves the two required companion files exist.
2. The desktop app lets the player choose one `.sav` file from any location.
3. The desktop app records new discoveries only from the companion's isolated
   event log.
4. The old Desktop backup importer and automatic save-path polling are removed.

Linux and SteamOS are intentionally out of scope. They require their own
distribution, game-location, and local-data design; an NSIS Windows installer
cannot make that support reliable.

## Installer

### Required companion payload

The companion payload has exactly two required runtime files:

- `MistriaTrackerCompanion/manifest.json`
- `MistriaTrackerCompanion/gml/MistriaTrackerCompanion.gml`

The installer compiles those files directly from the public source tree. The
Windows build must fail before artifact upload if either source file is absent.

### Installation behaviour

When the player selects the optional companion:

1. Resolve a Fields of Mistria directory automatically only when it contains
   `assets.zip`; otherwise ask the player to select that game folder.
2. Create `mods/MistriaTrackerCompanion` under the validated game folder.
3. Preflight the exact destination for write access.
4. Extract the companion payload there without recursively deleting any game
   mod folder or unrelated mod files.
5. Verify both required files exist after extraction.

If any companion step fails, the desktop Tracker installation still completes.
Setup shows one clear failure message with the exact destination and tells the
player to rerun setup as an administrator if Fields of Mistria is installed
under a protected folder. It must not expose NSIS Abort/Retry/Ignore prompts
for the expected write failure path.

The installer continues to request elevation because a default Steam library
under Program Files needs it to write the optional game mod. It never modifies
game saves.

## Explicit save import

### User experience

Options contains one button: **Load save file**. It opens the native file
picker filtered to `.sav` files. The player deliberately selects one save from
any accessible location, including a secondary drive or synced folder.

There is no automatic Desktop folder, automatic save discovery, background
save polling, or broad filesystem scan.

The result clearly reports one of these outcomes:

- discoveries imported for the selected profile;
- the exact same save was already imported;
- the selected file is not a supported Fields of Mistria save;
- the selected game-save version is not yet approved for import.

### Safety boundary

The frontend passes only the user-selected path to a native command. The
backend canonicalizes it, accepts only a regular `.sav` file, snapshots it
into Tracker-owned local storage using the existing bounded snapshot service,
parses only that temporary snapshot, and removes the snapshot and manifest
afterward. The original selected save is read-only throughout.

The chosen save filename supplies the profile identifier only after existing
filename validation. Parsed data is committed transactionally to Tracker's
own database. Existing tracker-database rollback backups stay unchanged.

The save parser remains fail-closed: Fields of Mistria 1.0.5 is enabled only
after the parser has passed an explicitly user-approved disposable-save test.
The button must say that the version is not approved rather than inventing an
empty profile or reporting success.

## Passive live tracking

The companion event log is the sole source for active-profile changes and new
discoveries while the game is running. `profile_activated` selects the active
Tracker profile, and later supported events update that profile.

The live tracker does not open game saves, infer the saves directory, or
reconcile a hard-coded `%LOCALAPPDATA%` path. A missing companion log leaves
the Tracker in a clear waiting state; after a player loads a save and changes
rooms once, the companion can create its isolated log.

## Cleanup and boundaries

Remove only the obsolete Desktop backup importer:

- Settings copy, state, button, and callback;
- frontend native bridge functions;
- Tauri command and Desktop/OneDrive path guesses;
- startup and polling calls that automatically import saves;
- tests and documentation that prescribe `Mistria Save Backups`.

Keep reusable, correctly scoped code:

- bounded `SnapshotService` temporary-copy logic;
- `.sav` parsing and compatibility checks;
- transactional Tracker database persistence and its own rollback backups;
- companion event parsing and passive log tailing.

Rename shared persistence operations so they describe recording imported save
discoveries rather than an obsolete "backup" source. No command or UI may
reference the removed Desktop backup concept after this patch.

## Verification and release gate

Tests must cover:

1. manual selected-save validation rejects folders and non-`.sav` files;
2. manual selected-save import snapshots and parses only the selected path;
3. an unsupported version returns a clear non-import result;
4. live event polling still switches the profile and records a new discovery
   without reading any save;
5. Settings exposes the explicit save picker flow but no Desktop backup UI;
6. the installer source declares the two required payload files and post-copy
   verification.

Before release, build the Windows installer from the 0.1.5 source, run the
test suite in the supported Node 24 environment, and manually verify these
installer paths:

1. default Steam library under Program Files;
2. a second Steam library or manual game-folder selection;
3. companion installation with both required files present;
4. a protected destination failure that reports a clear message instead of
   Abort/Retry/Ignore.

Then test manual import on a user-approved disposable save and one new live
discovery through AIM or MOMI. Release a new version and checksum as 0.1.5;
never replace the published 0.1.4 asset or checksum.
